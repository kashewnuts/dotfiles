# プランを docs に出力

プランファイルの内容をプロジェクトの `docs/` ディレクトリに整形して出力する。

## 入力

`$ARGUMENTS` には出力ファイル名を指定する (例: `feature_design.md`)。空のときはプランのタイトルからファイル名を生成する。

## 処理手順

1. **プランファイルの検出**
   - `~/.claude/plans/` ディレクトリから最新のプランファイルを検出する
   - 会話中でアクティブなプランファイルがあれば、そちらを使う

2. **プラン内容の読み込み**
   - プランファイル (.md) を読み込む
   - H1 のタイトルを抽出する

3. **ドキュメント用に整形**
   - 以下のセクションを **除外**:
     - 「実装手順」「実装ステップ」
     - 「検証方法」。簡略化して残してもよい
     - 「次のステップ」「TODO」
   - 以下のセクションを **保持**:
     - 「概要」「目的」
     - 「現状分析」「背景」
     - 「設計」「アーキテクチャ」
     - 「推奨アプローチ」
     - 「注意事項」「制約」

4. **出力ファイル名の決定**
   - `$ARGUMENTS` が指定されている場合はそれを使う
   - 未指定の場合はタイトルをスネークケースに変換する (例: `feature_xyz_design.md`)

5. **docs/ ディレクトリへの出力**
   - `docs/` ディレクトリが存在しない場合は作成する
   - 整形したドキュメントを出力する

## 出力フォーマット

```markdown
# [プランのタイトル]

> このドキュメントは Claude Code のプランから自動生成されました。
> 生成日: YYYY-MM-DD

## 概要

[プランの概要セクション]

---

## 背景・現状分析

[現状分析セクション]

---

## 設計・アプローチ

[設計/推奨アプローチセクション]

---

## 注意事項

[注意事項セクション]

---

## 参考

- 元プランファイル: `~/.claude/plans/xxx.md`
```

## 整形ルール

1. **セクション順序の正規化**
   - 概要 → 背景 → 設計 → 注意事項 の順に並べ替える

2. **技術的詳細の調整**
   - コマンド例は参考情報として役立つので保持する
   - 具体的なファイルパスは保持する

3. **不要な情報の除去**
   - 手順を 1 つずつ書いた Bash コマンドの実行手順
   - チェックボックス形式の TODO リスト
   - 「完了」「済」などのステータス表記

## 注意事項

- プランファイルが見つからない場合はエラーメッセージを表示する
- 既存ファイルがある場合は上書きしてよいか確認する
- Git 管理下の場合は変更をステージングせず、ユーザーに任せる
